# Tech Baseline — Saintber.Forge

> Purpose  
> 定義 Saintber.Forge 專案的**最低技術基線**（版本、相容性與最小依賴假設），  
> 以降低跨工具與多入口（InnerApi / OuterApi / Blazor Server / WASM）並存時的整合成本。

> Scope  
> 本文件僅描述**技術版本與最低相容要求**。  
> 不描述結構、不描述分層責任、不描述安全機制（安全基線另見 `security-baseline.md`）。

---

## 一、.NET 與語言版本

### 1. 最低 .NET 版本

- 專案最低目標框架：`.NET 8`（`net8.0`）
- 允許使用更新版本（例如 `net9.0`），但：
  - 不得要求其他工具或入口同步升級
  - 不得引入只能在更新版本運作且無替代方案的關鍵能力

---

### 2. C# 語言版本

- 使用對應 TFM 的預設 C# 語言版本
- 允許使用 preview 語言特性，但需符合：
  - 可移除（可回退至非 preview 寫法）
  - 不作為跨工具共用契約的必要條件

---

## 二、前端技術基線（非結構性）

### 3. RWD 最低要求

前端 UI 需符合 RWD 需求：

- 主要互動流程在常見桌機與手機寬度下可用
- 不得以固定寬度或僅桌機視角為唯一設計前提
- 視覺與互動規範由前端專案自行實作，本文件僅定義最低要求

---

## 三、資料存取技術基線（非結構性）

### 4. EF Core 使用原則

若採用 Entity Framework Core：

- EF Core 版本需與入口專案與工具的 TFM 相容
- 不得依賴特定資料庫 provider 的非必要特性作為核心邏輯前提
- 需保留替換 provider 或調整資料庫類型的可能性

---

## 四、依賴與相容性

### 5. 依賴版本一致性

- 同一個入口專案（例如 OuterApi）內的相依套件版本應保持一致
- 共用套件（logging、config、serialization 等）版本差異需可被控管
- 不得引入會造成依賴地獄（diamond dependency）且無收斂策略的套件組合

---

## 五、例外與演進

### 6. 偏離基線

若某工具或入口需要偏離本基線（例如使用更高版本或特殊套件）：

- 必須能說明其必要性
- 必須能提供回退或替代方案
- 不得要求整體同步調整以配合單點需求
