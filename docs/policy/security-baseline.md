# Security Baseline — Saintber.Forge

> Purpose  
> 定義 Saintber.Forge 專案在**安全相關技術與實作上的最低基線**，  
> 以在維持彈性與可演進性的前提下，避免不必要的安全風險累積。

> Scope  
> 本文件屬於工程政策層（Policy），  
> 僅描述安全相關的技術能力與使用原則，  
> 不定義治理裁決、不描述結構配置、不強制所有功能套用。

---

## 一、安全基線的定位

### 1. 安全為能力，而非預設

Forge 採取以下安全觀點：

- 安全機制為**可啟用的能力**
- 非所有 API 或功能皆必須啟用身份識別或授權
- 是否啟用安全機制，應依使用情境與風險評估決定

---

## 二、身份識別與授權基線

### 2. 支援的身份識別技術

Forge 預設支援以下身份識別與授權技術：

- JWT（JSON Web Token）
- OpenID Connect（OIDC）

上述技術可單獨或搭配使用，  
但不得假設所有消費者皆具備身份。

---

### 3. 非強制原則

- 身份識別與授權並非所有 API 的強制要求
- 可存在完全公開、無需身份驗證的 API
- 公開 API 需明確標示其「無授權」屬性

---

## 三、API 安全邊界

### 4. InnerApi 與 OuterApi 的安全定位

- **InnerApi**
  - 預設位於受信任網路
  - 可假設基礎網路隔離存在
  - 是否啟用身份驗證視實際風險決定

- **OuterApi**
  - 對外可達
  - 不得假設呼叫端可信
  - 是否啟用身份識別與授權需明確決策

---

### 5. API 不得內建信任假設

- API 不得因部署位置而隱含信任呼叫端
- 安全假設需明確存在於設定或文件中
- 不得以「目前只有內部使用」作為永久理由

---

## 四、Token 使用原則

### 6. Token 的角色限制

- Token 僅用於身份識別與授權判斷
- 不得作為業務資料或狀態載體
- 不得承載敏感資料（如密碼、金鑰）

---

### 7. Token 壽命與刷新

- Token 應具備明確的有效期限
- 長期存取需求應搭配刷新機制
- 不得依賴永久有效的 Token 作為正常流程

---

## 五、前端安全基線

### 8. 前端信任邊界

- 前端（Blazor Server / WASM）不得被視為可信來源
- 所有安全判斷必須在 API 端完成
- 前端僅負責提供使用者互動介面

---

### 9. Blazor Server 特性注意事項

- Blazor Server 為長連線模型
- 不得假設連線存在即代表授權持續有效
- 需能處理連線中斷與重新驗證情境

---

## 六、設定與秘密管理

### 10. 秘密資訊處理原則

- 金鑰、憑證、Client Secret 不得硬編碼於程式碼中
- 秘密資訊應由設定或安全儲存機制提供
- 不得將秘密資訊提交至版本控制系統

---

## 七、例外與演進

### 11. 安全例外處理

若某功能或工具無法符合本安全基線：

- 必須明確記錄原因
- 必須說明風險承擔範圍
- 不得將例外視為預設狀態

---

### 12. 基線調整原則

- 本文件可隨安全需求演進而調整
- 調整目標應為降低長期風險與治理成本
- 若調整影響治理方向，應回到憲章層重新評估

---
