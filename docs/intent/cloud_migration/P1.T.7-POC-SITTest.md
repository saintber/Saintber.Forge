## Intent v1.0 – Initial Request

### Source
- Origin: Customer
- Provided by: Elsa
- Context: Meeting

### Project Context (At That Time)
- 上雲計畫目前進行到 POC 建置的 P1.2.2（DI/IOC 注入完成）
- 正在進行 P1.2.3（EFCore 導入）
- 原計畫於 P1.3 完成後才進行 P1.T.7
- 因 SDD 教育訓練需求，決定提早進行 P1.T.7

### Original Description (As-Is)
- 需要建置一組可驗證系統架構可行性的 API，
- 用以確認 MAS 原有周邊服務在雲端化／容器化後仍可正常使用。
- 該工具未來亦可作為周邊服務疏通測試或系統健康度驗測用途。

- 連線參數需透過系統參數配置。
- 應具備可停用之開關，以避免遭未授權使用。
- 應支援開發者本機環境與上雲環境之切換。
- 以下列出的周邊系統連線項目，為本次 P1.T.7 驗測工具的目標驗證範圍，
  > 均需納入實作與驗證；其驗證層級以「可成功連線並完成基本通訊」為主，
  > 不涵蓋完整業務流程或資料正確性驗證。
    - GKE => Redis, redis
    - GKE => GCS, http/https
    - GKE => Postgres SQL, PSQL
    - Internet => GKE, http/https
    - GKE => Fda API(internet), https
    - GKE => 統一企業 FTP(internet), FTP
    - GKE => 超商 SFTP(intranet), SFTP
    - GKE => PTC WebService(internet), http/https
    - PTC => GKE WebService(internet), http/https
    - GKE => 超商 MailRelay(internet), SMTP

### Why This Matters
- 作為 SDD 教育訓練的範例。
- 同時驗證整體系統架構可行性。
- 未來亦可保留作為系統架構的健康度測試用。

### Known Ambiguities
- 因 P1.3 尚未完成，故無法同時驗證底層元件改寫後是否正常。

## Intent v1.1 – Spec elaboration

### Change Trigger
- SD 確認系統現行狀況後，補充周邊串接所需之參數來源與參數鍵（parameter contract）

### Updated Intent (Delta Only)
- 周邊串接與組態參數來源：透過系統參數機制取得（現行由 DBCMManager 提供）
- 各周邊串接所需參數鍵如下（未確認者保留 Unknown）：
  - Redis：Unknown
  - GCS：Unknown
  - Postgres：
    - DB 連線驗測需沿用 MAS 既有的 DbContext 抽象（`IMasDbContext`），以避免繞過既有資料存取層設計。
    - `IMasDbContext` 定義於 `Mas_Library/Pic.Mas.Persistence.EF.Abstractions`
  - Fda API：
    - apiKey: ("AD","fda_api_key","01")
    - secureKey: ("AD","fda_secure_key","01")
    - SRU1: ("AD","fda_url","01")
    - SRU2: ("AD","fda_url","02")
  - 統一企業 FTP：
    - ip: ("CR","crt011","ftp_server")
    - username: ("CR","crt011","ftp_username")
    - password: ("CR","crt011","ftp_pwd")
  - 超商 SFTP：
    - ip: ("CR","crt011","sftp_server")
    - port: ("CR","crt011","sftp_port")
    - username: ("CR","crt011","sftp_username")
    - password: ("CR","crt011","sftp_pwd")
  - PTC WebService：
    - url: ("CR","crt015","ws_url")
  - MailRelay：
    - Server1: ("BU","mail_server", sender/host/port/c_user/c_pwd/use_ssl)
    - Server2: ("BU","mail_server_02", sender/host/port/c_user/c_pwd/use_ssl)

> 本次補充僅描述參數契約與串接前提；DB 驗測的具體技術作法（例如是否使用泛型 DbContext 以執行最小連線驗證）屬於 Spec/Implementation 細節，應以對應 Spec 與 integration notes 為準。
> 具體呼叫方式與 request 範例詳見 `P1.T.7-POC-SITTest.integration-notes.md`。
